# Почему сайт был медленным и что исправлено

## Причина
Сайт распознаёт речь **прямо в браузере** (Whisper через WASM), а не на
сервере. Это и есть корень проблемы — три накладывающихся эффекта:

1. **Модель по умолчанию — Small (~250 МБ).** Она и скачивается дольше, и
   считает медленнее, чем Tiny/Base. Из-за неё даже маленький файл (254 КБ)
   ждёт 1.5–2 минуты — это не транскрипция, а загрузка и инициализация
   250-мегабайтной модели.
2. **WASM считает в один поток.** Библиотека поддерживает многопоточность,
   но браузер включает её только на "cross-origin isolated" страницах
   (нужны спец. HTTP-заголовки на хостинге). Без них даже 8-ядерный ПК
   использует одно ядро.
3. **Платный сервис гоняет ту же модель на GPU-сервере.** Сравнение с
   локальным CPU в браузере в моменте нечестное — в браузере всегда будет
   медленнее. Это не баг, а другая архитектура. Полностью догнать GPU-сервис
   без переноса распознавания на свой сервер/API нельзя, но разрыв можно
   сильно сократить (см. ниже).

## Что изменено в коде
- `index.html`: модель по умолчанию — **Base** вместо Small (в разы быстрее
  скачивание и счёт; Tiny — ещё быстрее, если точность не критична).
- `app.js`:
  - фоновая "прогрева" теперь заранее подгружает веса модели Base/Tiny,
    пока пользователь ещё читает страницу — к моменту загрузки файла
    модель уже в кеше браузера;
  - включена поддержка многопоточного WASM (`numThreads`), она активируется
    автоматически, если хостинг отдаёт нужные заголовки (см. ниже) —
    иначе безопасно работает как раньше, в один поток.
- Скрипты (`lucide`, `wavesurfer`, `jspdf`, `docx`) переключены с `unpkg.com`
  на `cdn.jsdelivr.net` — jsdelivr отдаёт заголовок
  `Cross-Origin-Resource-Policy`, без которого cross-origin-изоляция
  (нужна для п.2) блокирует их загрузку.

## Опционально: включить многопоточность (заметный прирост скорости)
Добавлены файлы `_headers` (Netlify / Cloudflare Pages) и `vercel.json`
(Vercel) — они включают заголовки `Cross-Origin-Opener-Policy` и
`Cross-Origin-Embedder-Policy`, без которых многопоточный WASM не
работает ни при каких настройках в коде.

**Важно:** это меняет поведение всей страницы (строгая изоляция ресурсов).
Проверьте после деплоя, что загружаются иконки, waveform-плеер и экспорт
в PDF/DOCX. Если что-то пропало — удалите `_headers`/`vercel.json`
(или строку про заголовки в панели хостинга) и сайт вернётся к прежнему
поведению (без ошибок, просто без многопоточности).

Если сайт лежит не на Netlify/Vercel/Cloudflare Pages (например, GitHub
Pages или свой сервер) — напишите, на чём хостится, дам конкретный конфиг
под вашу платформу (GitHub Pages кастомные заголовки не поддерживает
вообще, там нужен обход через Cloudflare или смену хостинга).

## Если и этого мало
Единственный способ выйти на скорость платных сервисов "в лоб" — считать
не в браузере, а на сервере/через API (Whisper API, Groq, свой сервер с
GPU). Это уже другая архитектура сайта (нужен бэкенд), могу помочь
спроектировать, если понадобится.
